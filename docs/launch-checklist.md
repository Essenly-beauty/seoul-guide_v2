### 2026-09-07 다이소 랭킹·상세 연결 검증

- `Ranking` 진입 후 하단은 `< Back | Olive Young | Daiso` 3개 제어로 바뀌며,
  리테일러 선택은 URL에 저장되고 `replace` 전환을 사용한다. 공용 5개 메뉴에서
  Ranking으로 진입할 때 동일 출처의 이전 경로를 검증·저장하므로 Navigation API나
  referrer가 없는 Safari에서도 Back이 이전 앱 화면으로 돌아간다. 저장값은 한 번만
  사용하고 외부 URL 및 Ranking 자체 경로는 거부한다.
- 다이소는 검증된 2026-08-31 CSV 3,046행에서 생성한 고유 상품 38개만
  사용한다. `Rising`, `Daily`, `Weekly`는 각각 원본 순위 1~20을 노출하고,
  카테고리 필터 뒤에도 원본 순위의 간격을 유지한다. 세 TOP20의 상품번호·원본
  순서 fixture는 런타임 선택기와 독립적으로 고정했고, 승인 CSV SHA-256
  `29b8d65c…32bcc`, 38개 전체 표시 필드 canonical SHA-256
  `64ff5d39…d975`, manifest SHA-256 `e67de59d…575e`를 검사한다.
- 상품 이미지가 없는 행은 플레이스홀더를 사용한다. 랭킹 행은 내부
  `/shop/daiso:<상품번호>` 상세로 이동하고, 상세에서만 검증된 CSV의 HTTPS
  다이소몰 `pdNo` 구매 링크를 새 탭으로 연다. 랭킹 행에서는
  가격·평점·리뷰 수·Source 날짜·별 아이콘·Parcel 문구를 제거하고 실제로 제공되는
  Pickup/Same-day만 태그로 표시한다. 검증된 가격·평점·리뷰 수는 상품 상세에서만 제공한다.
- 다이소 매장 전체 상세에는 Daily 상위 4개의 체인 전체 랭킹 미리보기를 제공하며,
  지점 재고가 아니라는 안내를 함께 표시한다. 상품 상세의 갤러리 상단에는
  Back/Share를 두고, 스크롤 시 Back·한 줄 제목·Share·더보기 고정 헤더가
  버튼 통과 비율에 맞춰 점진적으로 나타난다.
- 랭킹 상단 제목은 선택 리테일러에 맞춰 `OLIVE YOUNG Ranking` 또는
  `DAISO Ranking`으로 표시된다. 다이소 보조 카테고리는 44px 바깥 터치 영역 안에
  36px 시각 필을 두며, 라이트·다크 테마별 텍스트 및 키보드 포커스 링 대비 계약을
  둔다.
- 지도 시트의 일반 행과 동일 좌표 선택 행은 모두 축소 가능한 `maprow-copy`
  래퍼를 사용한다. 목록 뷰포트는 가로 오버플로를 숨겨 긴 이중 언어 이름과 주소가
  시트 너비 밖으로 수평 스크롤을 만들지 않게 했다.
- 자동 게이트 재검증(2026-09-08): 이번 변경 관련 집중 테스트는 3파일 31/31 통과했고,
  전체 `npm run verify:predeploy`도 끝까지 통과했다. 타입 검사와 ESLint 경고·오류가
  없었고, 전체 Vitest는 65파일 688/688를 통과했다. 장소 감사 최신성 검사는
  `total=851`, `approximatePins=42`, `missingHours=194`, `cachedKakao=364`,
  `naverEnglishUnchecked=834`, `uncheckedIdentity=833`을 확인했다. Next.js 프로덕션
  빌드는 정적 페이지 44/44를 생성했다.
- 전체 사진 장소 확장(2026-09-12): 오너가 전달한 160개 원본 폴더의 613장을
  모두 반영했다. SPA 1899와 SPA 1978은 같은 현재 장소로 통합되어 사진이 있는
  공개 장소는 159곳이며, 전체 공개 지도는 845곳이다. 정확한 주소 좌표가 확인되지
  않은 99곳은 `Provisional location`/`Approximate pin`을 화면에 표시하고
  지도 서비스에서 지점을 재확인하도록 안내한다. 이 장소에는 검증되지 않은 별점,
  리뷰 수, 가격대, 영업시간을 만들지 않았다. 전체 `npm run verify:predeploy`에서
  타입 검사·ESLint·Vitest 69파일 712/712·감사 최신성·프로덕션 빌드 44/44를
  통과했다.
- `npx playwright test e2e/ranking-retailers.spec.ts --list`는 Chromium 시나리오
  10개(1파일)를 발견했다. 이는 브라우저 실행 결과가 아니다. 로컬 QA는
  재사용 서버가 아닌 `127.0.0.1:3001` 전용 서버와 QA 환경변수를 강제해 빈 상태가
  404일 때 조용히 건너뛰지 않는다. 이 실행 환경은 localhost 바인딩을 `EPERM`으로
  거부하고 외부 배포 주소 DNS도 해석하지 못해 실제 브라우저 실행은 아직
  완료되지 않았다. 정확한 배포 SHA에서 아래 명령을 다시 실행해야 한다.

```bash
E2E_EXTERNAL_ONLY=1 E2E_BASE_URL=https://<deployment> \
  npx playwright test e2e/ranking-retailers.spec.ts

# WebKit 설치 후 Safari 엔진 회귀(로컬 전용 QA fixture 포함)
npx playwright install webkit
E2E_WEBKIT=1 npx playwright test e2e/ranking-retailers.spec.ts \
  --project=webkit-ranking
```

배포 환경에는 QA 전용 빈 상태 경로가 노출되지 않는다. `/ranking/qa`는
Playwright가 시작한 서버에만 서버 환경변수로 활성화되며 일반 실행에서는 404다.

### Place data audit

`npm run audit:data`를 실행하고 `reports/place-audit.md`를 검토한다. 이
명령은 외부 지도 서비스에 요청하지 않으며 장소 레코드를 변경하지 않는다.
`unchecked does not mean invalid`이며, 리포트는 `no automatic deletion` 또는
자동 숨김을 수행하지 않는다.

장소를 검토한 뒤에는 판정, 검토자, 검토일, 메모, 근거 링크만
`data/place-audit-verdicts.json`에 추가하고 리포트를 다시 생성한다. 외부 리뷰
본문을 붙여 넣거나 지도 서비스의 사진·스크린샷을 저장하지 않는다. 공급자 간
결과가 충돌하면 상호·지점·주소·업종·핀을 함께 확인할 때까지 `ambiguous`로
유지한다.

영문명은 `englishSupport`와 별개인 `naverEnglish` 판정으로 관리한다. 리포트의
`Naver (EN)` 링크는 서비스에 노출된 영문명만 그대로 검색하므로, 같은 장소가
나오지 않으면 영문명을 먼저 교정 대상으로 둔다. 내부 카탈로그 962곳 전수 대조는 네이버 지도
글로벌 UI에서 영문명 그대로 검색한 결과와 한글 상호명+주소 검색 결과를 차례로
비교한다. 긍정 일치 판정은 장소 상세 URL을 근거로 기록하고 리뷰
본문·사진·스크린샷은 복제하지 않으며, 아직 직접 확인하지 않은 행은
`unchecked`로 유지한다.
`matched` 판정은 해당 장소의 숫자 Naver place ID와 그 ID가 일치하는 장소 상세
URL을 함께 기록해야 한다. `not_found`·`ambiguous` 같은 비일치 판정은 검색 URL을
근거로 사용할 수 있지만, 검토자·검토일·판단 메모를 반드시 함께 남긴다.

공개 화면은 `PLACES`, 내부 감사는 `CATALOGUE_PLACES`를 사용한다. 현재
내부 카탈로그는 962곳이고 공개 카탈로그는 845곳이다. 따라서 검증 보류 장소를
지도·검색·카테고리·상세·사이트맵에서 일관되게 제외해도 전체 원본과 판정 이력은
사라지지 않는다. 공개 가능한 데이터가 없는 카테고리
칩도 함께 감춰 빈 결과 화면으로 유도하지 않는다. 공개 경계는 curated·수동 숨김뿐
아니라 서울 밖 주소/zone과 빈 주소도 차단한다. 단, 전수 노출 대상으로 명시된
`geoSource: area` 근사 핀은 `locationVerification: provisional`인 경우에만 공개하고
지도 시트와 상세에서 근사 위치임을 알린다. 정확한 주소·좌표가 확인되면 검증 패치로
교체하고 회귀 테스트를 통과시키며, 라벨 없는 근사 핀은 계속 차단한다.
다이소 251곳은 공식 서울 매장 스냅샷을 근거로 먼저 공개한 별도 정책이며,
`nameVerification: provisional` 상태를 유지해 Naver/Google 검증 완료로 오인되지 않게 한다.
두 총계는 `lib/data.test.ts`의 공개 경계 계약으로 계산하고, `npm run audit:data`가
내부 카탈로그 962곳을 다시 집계한다. 수동으로 별도 장소 수를 관리하지 않는다.
