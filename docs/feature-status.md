| `/design` | **구현** | semantic 토큰, 타입 스케일, 버튼·아이콘 버튼·칩과 기초 컴포넌트를 조작 가능한 형태로 보여준다. | 개발 기준 화면이며 사용자 내비게이션에는 노출하지 않는다. 기준 문서는 `docs/design-system.md`다. |
| 디자인 시스템 계약 | **구현** | 공통 컴포넌트와 접근성 계약을 테스트로 보호한다. 현재 기준 테스트 기록은 183/183이다. | 시각 회귀, 실제 모바일 기기, 스크린리더, 다국어 길이 검증을 모두 대체하지는 않는다. |

### 3.8 레거시 호환 라우트

다음 5개 라우트는 독립 화면이 아니라 기존 링크 호환용 리다이렉트다. 상태는 **구현(호환 경로)** 이며 새 기능이나 별도 데이터는 없다.

| 이전 라우트 | 이동 대상 |
|---|---|
| `/home` | `/map` |
| `/shop` | `/ranking` |
| `/journal` | `/blog` |
| `/journal/[slug]` | `/blog/[slug]` |
| `/mypage` | `/menu` |

라우트 별칭은 `lib/routes.ts`에서 관리한다.

## 4. 핵심 사용자 흐름 판정

| 흐름 | 판정 | 확인된 범위 |
|---|---|---|
| 로그인 → 지도 | **프로토타입** | 이동은 되지만 로그인은 발생하지 않는다. |
| 온보딩 → 개인화 | **프로토타입** | 1·2단계 일부 값만 로컬 저장된다. 지도·랭킹 추천과의 연결은 제한적이며 3단계는 저장되지 않는다. |
| 현재 위치 → 주변 장소 탐색 | **구현** | 위치 권한, fallback, 지도·목록 동기화, 필터, 영역 재검색이 동작한다. 데이터 범위는 샘플이다. |
| 검색 → 장소 선택 → 지도 중앙 이동 | **구현** | 검색 결과의 `place` query를 통해 선택 마커와 콜아웃이 열린다. |
| 출발역·도착역 검색 → 경로 → 역별 주변 장소 | **구현** | 로컬 경로 계산, 환승, 경유역, 역 이동과 반경 필터가 동작한다. 실시간 교통 정보는 없다. |
| 장소 → Google·Kakao·Naver 길찾기 | **외부 위임** | 실제 외부 지도 URL로 전달한다. |
| 장소 → 예약·결제·취소 | **프로토타입** | 전체 화면 흐름은 체험할 수 있으나 어떤 거래도 생성되지 않는다. |
| 제품 랭킹 → 상세 → 근처 판매 채널 | **구현** | 샘플 상품 탐색과 지도 카테고리 연결은 된다. 순위·재고·온라인 구매는 운영 데이터가 아니다. |
| 저장 → Saved 목록 반영 | **프로토타입** | 같은 브라우저의 `localStorage` 범위에서 동작한다. |
| 예약 후 리뷰 작성 | **프로토타입** | 입력과 완료 이동만 있으며 예약 검증·리뷰 저장·게시가 없다. |
| 알림 설정 → 이메일·푸시 수신 | **미구현** | 설정 UI만 있고 구독 저장과 발송 인프라가 없다. |
| 피드백 제출 → 운영팀 접수 | **미구현** | 입력 결과가 서버로 전송되지 않는다. |
| 여행 생성·관리 | **미구현** | 고정 여행 카드 외에 생성·편집·저장이 없다. |
| 키트 신청 → 준비·수령 | **프로토타입** | 설문 완료 화면만 있으며 신청·재고·배송 상태는 연결되지 않는다. |

## 7. 현재 서비스의 정확한 표현

현재 Essenly는 다음과 같이 표현하는 것이 정확하다.

> 외국인 서울 방문자를 위한 K-beauty 지도·지하철·장소·상품 탐색 경험을 검증하는 프론트엔드 프로토타입. 지도와 지하철 경로 계산, 로컬 검색 및 상세 탐색은 동작하지만 계정, 예약, 결제, 재고와 운영 데이터는 아직 연결되지 않았다.

“로그인 완료”, “예약 확정”, “결제 완료”, “실시간 재고”, “운영 중 알림” 같은 표현은 현재 구현 상태를 과장하므로 외부 소개 자료에서 사용하지 않는다.
