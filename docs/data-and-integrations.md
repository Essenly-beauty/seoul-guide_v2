# 데이터 및 외부 연동 현황

> 기준 커밋: `563950d`  
> 점검일: 2026-07-26  
> 문서 목적: 현재 프로토타입에서 **실제로 동작하는 데이터와 연동**을 명시하고, 출시를 위해 필요한 **목표 구조**와 구분한다.

## 1. 한눈에 보는 현재 상태

Essenly는 Next.js App Router 기반의 프론트엔드 프로토타입이다. 화면, 검색, 지도 탐색, 지하철 경로 계산과 개인화 UI는 구현되어 있지만, 서비스 데이터를 관리하는 API·DB·인증 서버는 아직 연결되어 있지 않다.

```text
현재

Next.js 클라이언트
├─ lib/data.ts 정적 샘플
├─ 커밋된 지하철 JSON/SVG 스냅샷
├─ 브라우저 localStorage
├─ 브라우저 GPS
├─ CARTO/OSM 지도 타일
└─ Kakao/Naver/Google 지도 딥링크
```

| 영역 | 현재 상태 | 운영 연결 여부 |
|---|---|---|
| 장소·제품·콘텐츠 | `lib/data.ts`의 메모리 상주 정적 배열 | 미연결 |
| 지하철 | 공개 자료로 빌드한 JSON/SVG를 저장소에 커밋 | 빌드 시점 스냅샷 |
| 사용자 계정 | 소셜 로그인 모양의 버튼이 `/map`으로 이동 | 인증 없음 |
| 사용자 상태 | 브라우저 `localStorage` | 서버 동기화 없음 |
| 지도 배경 | CARTO Voyager 래스터 타일, OSM 저작자 표시 | 런타임 외부 요청 |
| 위치 | 브라우저 Geolocation API | 사용자 권한 기반 |
| 길찾기 | Kakao Map·Naver Map·Google Maps 웹 딥링크 | 외부 서비스로 이관 |
| 예약 | 채널 선택 후 안내 토스트 | 실제 예약 연동 없음 |
| 결제·재고·CMS·분석 | 구현되지 않음 | 미연결 |

현재 `app/` 아래에는 서버 API Route Handler가 없고, 패키지에도 인증·DB SDK가 없다. Google·Apple·Kakao 로그인 버튼은 OAuth를 시작하지 않으며 세 버튼 모두 지도 화면으로 이동한다.

## 2. 애플리케이션 데이터

### 2.1 정적 샘플 데이터

`lib/data.ts`가 장소, 제품, 콘텐츠의 단일 데이터 소스 역할을 한다. 검색·지도·랭킹·상세 화면은 이 배열을 클라이언트에서 필터링하고 정렬한다.

| 데이터 | 수량 | 포함 정보 | 현재 한계 |
|---|---:|---|---|
| `PLACES` | 44 | 이름, 유형, 주소, 좌표, 평점, 영업시간, 서비스, 언어 지원 등 | 항목별 원천·절대 검증일·외부 사업자 ID 없음 |
| `PRODUCTS` | 14 | 브랜드, 카테고리, 피부 유형, 고민, 편집 태그, 샘플 랭킹 등 | 가격 숫자·지점 재고·실시간 판매 순위 없음 |
| `ARTICLES` | 3 | 제목, 태그, 게시일, 예상 읽기 시간 | CMS·작성자·개정 이력 없음 |

이 숫자는 구현 밀도를 의미할 뿐, 서울 전체의 데이터 커버리지나 운영 검증을 의미하지 않는다. 특히 평점, 평점 수, 영업시간, 가격, `English OK` 같은 현장 의사결정 정보는 출시 전에 출처와 검증 일자를 갖춰야 한다.

제품 타입에는 `onlineUrl`과 `onlineUrlVerifiedAt` 필드가 마련되어 있지만 현재 14개 제품 모두 검증된 구매 URL이 없다. 따라서 제품 상세에서 지점별 재고나 구매 가능 여부를 보장할 수 없다.

### 2.2 장소와 역의 1 km 커버리지

현재 장소 좌표와 지하철역 중심 좌표 사이의 Haversine 직선거리를 사용해 측정한 결과다.

| 지표 | 현재 값 |
|---|---:|
| 1 km 안에 장소가 하나 이상 있는 역 | 58 / 600 (9.7%) |
| 1 km 안에 Olive Young이 하나 이상 있는 역 | 19 / 600 (3.2%) |
| 등록된 Olive Young 지점 | 6 |
| 등록된 Daiso 지점 | 0 |

이 수치는 **역 출구 기준 도보 거리나 실제 보행 시간**이 아니다. 앱도 이를 역 중심 기준의 직선 반경으로 표시한다. Daiso는 데이터가 연결되지 않았다는 빈 상태를 보여주고, 사용자가 직접 확인할 수 있도록 해당 역 이름으로 Naver Map 검색을 연다.

현재 데이터로는 강남·명동·홍대 등 샘플 밀집 지역의 경험을 검증할 수 있지만, 수도권 600개 역 전체를 지원한다고 표현해서는 안 된다.

## 3. 지하철 데이터

### 3.1 커밋된 스냅샷

앱은 런타임에 지하철 API를 호출하지 않는다. 공개 원천을 개발 시점에 내려받아 가공한 뒤 다음 결과물을 저장소에 커밋한다.

| 결과물 | 규모 | 용도 |
|---|---:|---|
| `lib/subway-data.json` | 20개 노선, 600개 역, 706개 연결 | 역 검색, 좌표, 노선, 환승, 소요시간 기반 경로 계산 |
| `components/subway/seoul-metro.svg` | 전체 노선도 SVG | 지하철 모드 시각화와 역 선택 |
| `components/subway/metro-svg.ts` | SVG 문자열 빌드 결과 | 앱 번들에서 노선도 렌더링 |

`lib/subway.ts`는 커밋된 그래프에서 결정론적으로 역 검색, 최단 경로, 환승과 이동시간, 역 주변 장소를 계산한다. 실시간 도착, 운행 지연, 공사, 막차, 출구 폐쇄 정보는 제공하지 않는다.

### 3.2 원천과 라이선스

| 원천 | 사용하는 정보 | 특성 |
|---|---|---|
| KRIC 전국도시철도역사정보표준데이터 | 한글·영문 역명, 노선, 환승, 위도·경도 | 공공누리 공개 데이터 |
| `vuski/seoulsubway` | 운행 노선 구성, 역 인접 관계, 구간 시간, 노선 색상 | MIT, 코드 내 지정 출처 문구 유지 |
| Wikimedia Commons `Seoul_subway_linemap_en.svg` | 영문 전체 노선도 기반 SVG | 저자 PD-self, 독립 제작 지도 |

노선도 SVG는 서울교통공사·KRIC·Kakao·Naver의 공식 노선도가 아니다. 독립 제작물을 앱 상호작용에 맞게 가공한 것이다.

재생성 명령은 다음과 같다.

```bash
npm run build:subway-data
npm run build:subway-svg
```

원천 파일은 `scripts/.cache/`에 내려받고, 빌드 스크립트가 이름 정규화, 노선 병합, 예정 노선 제외, 알려진 좌표 오류 보정과 무결성 검사를 수행한다. 동일 캐시에서는 결과가 결정론적이어야 한다.

### 3.3 해석 시 주의점

- 지하철 그래프는 최신 스냅샷이지 실시간 운행 정보가 아니다.
- 구간 시간은 `vuski/seoulsubway`의 연결 데이터를 기반으로 하며, 실제 승강장 이동·혼잡·대기시간을 보장하지 않는다.
- KRIC 원천 누락이나 명칭 차이는 빌드 스크립트의 명시적 매핑과 제외 목록으로 다룬다.
- 노선 개통·역명 변경·폐역이 발생해도 자동 반영되지 않는다. 원천 재수집, diff 검토, 재빌드와 배포가 필요하다.
- 역 주변 장소는 역 중심 좌표와 장소 좌표의 직선거리로 연결된다. 출구별 보행 네트워크 데이터는 없다.

## 4. 브라우저에 저장되는 사용자 상태

현재 사용자 상태는 다음 `localStorage` 키에 저장된다.

| 키 | 내용 |
|---|---|
| `essenly.favorites` | 장소·제품·콘텐츠 즐겨찾기 |
| `essenly.profile` | 국적, 체류 형태, 관심사, 피부·헤어·언어·예산 프로필 |
| `essenly.feedback` | 사용자가 제출한 피드백 |
| `essenly.recentSearches` | 최근 통합 검색어 |
| `essenly.recentSubwayStations` | 최근 선택한 지하철역 |
| `essenly.myrating` | 장소별 개인 평점 |

이는 서버 저장이 아니다. 따라서 다음 제약이 있다.

- 브라우저나 기기를 바꾸면 동기화되지 않는다.
- 사이트 데이터를 삭제하거나 비공개 모드를 사용하면 사라질 수 있다.
- 사용자 계정, 접근 제어, 서버 백업, 운영자 조회가 없다.
- 피드백은 운영팀으로 전송되지 않는다. 브라우저 저장 실패 시 현재 구현은 제출 메시지를 보여주더라도 데이터를 잃을 수 있다.
- 민감정보, 연락처, 예약정보, 의료 관련 정보는 현재 구조에 저장해서는 안 된다.

`docs/user-data-strategy.md`의 Supabase 스키마는 목표안이며 현재 설치되거나 연결된 구조가 아니다.

## 5. 실제 외부 연동

### 5.1 지도 타일

Leaflet이 `basemaps.cartocdn.com`의 CARTO Voyager 래스터 타일을 런타임에 요청하고 OSM 및 CARTO 저작자를 표시한다. 이 기능은 네트워크 연결과 외부 타일 서비스의 가용성·이용 정책에 의존한다.

출시 전에는 타일 사용량 정책, 캐시 정책, 장애 시 대체 화면, 외부 요청에 따른 개인정보 고지를 확인해야 한다.

### 5.2 현재 위치

브라우저 Geolocation API로 위치 권한을 요청한다. 요청 제한 시간은 8초이며 최근 위치는 최대 60초까지 허용한다. 권한이 거부되거나 위치를 가져오지 못하면 지도는 강남역 좌표를 기본 중심으로 사용한다.

GPS 값은 사용자 기기의 측정치이며 앱 서버로 저장되지 않는다. 정확도는 실내·도심 환경과 기기 설정에 따라 달라질 수 있다.

### 5.3 외부 지도 딥링크

Kakao Map, Naver Map, Google Maps의 웹 URL을 생성해 목적지 검색 또는 길찾기를 외부 서비스에 맡긴다. SDK나 장소 검색 API를 통합한 것이 아니며 API 키도 사용하지 않는다.

- 위치 권한이 있으면 출발지와 목적지 좌표를 URL에 포함한다.
- 위치 권한이 없으면 목적지 검색 또는 목적지 중심 링크를 연다.
- 실제 경로, 소요시간, 대중교통 상태는 외부 지도 서비스가 계산한다.
- 외부 서비스의 URL 규격 변경은 앱 기능에 영향을 줄 수 있다.

예약 채널 시트의 Naver·Kakao·Instagram 항목은 현재 외부 예약 URL을 열지 않고 안내 토스트만 보여준다. 지도 딥링크와 예약 연동을 같은 수준의 기능으로 간주하면 안 된다.

### 5.4 공유와 클립보드

지원 브라우저에서는 Web Share API를 사용한다. 지원하지 않으면 공유할 텍스트나 URL을 클립보드에 복사한다. 공유 대상 앱의 동작과 성공 여부는 운영체제 및 브라우저에 의존한다.

### 5.5 그 밖의 런타임 외부 자원

전역 CSS가 Google Fonts를 `@import`한다. 폰트 요청 실패 시 시스템 대체 글꼴로 표시될 수 있으므로, 출시 정책에 따라 자체 호스팅 또는 Next.js 폰트 최적화를 검토해야 한다.

## 6. 데이터 신뢰도

| 데이터군 | 현재 신뢰 수준 | 판단 근거 |
|---|---|---|
| 지하철 역명·좌표·연결 | 중상 | 공개 원천 병합, 명시적 보정, 빌드·무결성 테스트가 있으나 스냅샷 |
| 지하철 실시간 상태 | 없음 | 실시간 API 미연결 |
| 장소 좌표·주소 | 프로토타입 | 샘플로 수록되어 있으나 레코드별 원천·검증일 없음 |
| 영업시간·가격·평점·언어 지원 | 프로토타입 | 변경 가능성이 높고 검증 이력·수집 기준 없음 |
| 제품 랭킹·추천 | 편집 샘플 | 공식 판매·리뷰 데이터 피드가 아님 |
| Olive Young 지점 재고 | 없음 | 지점별 재고 API 미연결 |
| Daiso 위치·재고 | 없음 | 장소 데이터 자체가 없음 |
| 사용자 프로필·즐겨찾기 | 해당 브라우저 한정 | `localStorage` 저장, 계정 동기화 없음 |
| 사용자 피드백 | 운영 미수신 | 브라우저에만 누적 |

UI 문구는 이 수준을 따라야 한다. 검증되지 않은 데이터에 `실시간`, `예약 가능`, `재고 있음`, `공식`, `도보 N분 보장` 같은 표현을 사용하지 않는다.

## 7. 출시 목표 구조

다음은 구현 완료 상태가 아니라 서비스 출시를 위한 목표안이다.

```text
목표

Next.js 앱
├─ 인증 제공자 (Google, 이후 Kakao)
├─ 서버 API 또는 Server Actions
├─ Postgres
│  ├─ profiles / consents
│  ├─ places / services / verification
│  ├─ products / retailers / availability
│  ├─ articles / revisions
│  ├─ favorites / ratings / bookings
│  └─ events / feedback
├─ 관리자 검수 도구 또는 CMS
├─ 데이터 수집·검증 작업
└─ 지도·예약·재고 제휴 연동
```

`docs/user-data-strategy.md`는 Google OAuth와 Supabase Postgres를 후보로 제안한다. 실제 도입 시에는 다음 경계를 유지한다.

- 브라우저는 권한이 필요한 데이터만 요청하고, 비밀키와 관리자 권한은 서버에 둔다.
- 계정 데이터, 동의, 즐겨찾기, 피드백은 사용자 ID에 귀속하고 RLS 또는 동등한 접근 제어를 적용한다.
- 장소·제품·콘텐츠의 공개 조회 모델과 운영 원천·검수 모델을 분리한다.
- 원천 수집 결과를 바로 노출하지 않고 정규화, 중복 제거, 검증, 승인 단계를 거친다.
- 외부 지도 딥링크는 유지하되 예약·재고는 실제 계약된 공급자의 식별자와 상태를 사용한다.

## 8. 데이터 갱신 원칙

### 8.1 모든 운영 레코드에 출처와 시간을 둔다

장소·서비스·제품에는 최소한 다음 메타데이터가 필요하다.

- `sourceType`, `sourceId`, `sourceUrl`
- `observedAt`, `verifiedAt`, `expiresAt`
- `verificationMethod`, `verifiedBy`
- `status` (`draft`, `verified`, `stale`, `closed`)

현재의 `priceConfirmedDaysAgo`처럼 기준일 없이 상대 기간만 저장하면 시간이 지나도 값이 갱신된 것처럼 보일 수 있다. 절대 시각을 저장하고 화면에서 상대 시간으로 변환한다.

### 8.2 사실과 편집 판단을 분리한다

주소, 좌표, 영업시간, 가격, 재고처럼 검증 가능한 사실과 `Editor’s Pick`, 추천 순위, 관광객 적합도 같은 편집 판단을 별도 필드와 이력으로 관리한다.

### 8.3 지하철은 버전이 있는 배포 데이터로 관리한다

- 원천 파일의 다운로드 일자, URL, 해시와 라이선스를 기록한다.
- 재빌드 시 역·노선·연결의 추가·삭제·변경 diff를 사람이 검토한다.
- 무결성 테스트와 대표 경로 회귀 테스트를 통과한 결과만 커밋한다.
- 화면에 실시간 데이터가 아니라는 점을 명확히 표시한다.

### 8.4 장소 커버리지를 수치로 관리한다

단순 장소 수보다 목표 관광 권역과 핵심 역 기준으로 관리한다. 예를 들어 역별·카테고리별 500 m/1 km 커버리지, 최근 검증 비율, 폐점 의심 비율, 영어 지원 검증 비율을 릴리스 지표로 둔다.

현재 기준값인 전체 장소 58/600, Olive Young 19/600, Daiso 0/600은 향후 데이터 확장의 비교 기준으로 사용한다.

### 8.5 재고와 예약은 확인 가능한 경우에만 주장한다

- 지점별 재고는 지점 ID, SKU, 조회 시각을 함께 받은 경우에만 표시한다.
- 예약 가능 시간은 예약 공급자가 반환한 슬롯과 만료 시각이 있을 때만 표시한다.
- 연동이 없거나 오래된 상태에서는 `재고 확인 필요`, `외부에서 확인`처럼 제한을 드러낸다.

### 8.6 사용자 데이터는 최소 수집한다

인증 도입 전까지 민감한 프로필과 연락처를 확대 수집하지 않는다. 도입 후에도 목적, 동의, 보존기간, 삭제 경로를 데이터 항목별로 정의하고, 기기 저장소에는 복구 가능한 비민감 UI 상태만 남긴다.

## 9. 출시 전 데이터 우선순위

1. **P0 — 진실한 표시:** 샘플·미검증·비실시간 상태를 UI와 운영 문서에 일관되게 표시한다.
2. **P0 — 장소 기준 확립:** 핵심 관광 권역의 장소 원천, 검증 책임자, 절대 검증일과 폐점 처리 규칙을 만든다.
3. **P1 — 계정 저장소:** 실제 OAuth, 사용자 DB, 동의·삭제·복구 흐름을 연결한다.
4. **P1 — 운영 파이프라인:** 장소·서비스·콘텐츠를 수정하고 승인할 수 있는 관리자 도구와 변경 이력을 구축한다.
5. **P1 — 피드백 수신:** 브라우저 저장이 아닌 서버 제출과 운영 알림을 연결한다.
6. **P2 — 제휴 연동:** 검증 가능한 예약 채널, 제품 구매 URL, 지점 식별자를 연결한다.
7. **P2 — 재고·실시간 정보:** 제공 계약과 신선도 기준이 확보된 데이터만 단계적으로 도입한다.

이 문서의 `현재 상태` 수치나 연결 여부가 변경되면, 기능 구현과 같은 커밋에서 함께 갱신한다.
