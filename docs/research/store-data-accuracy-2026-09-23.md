### 1-2. 왜 이렇게 됐나 — 출처가 공식이 아니다

## 4. 재현 방법

```bash
# 다이소 — 기록된 요청 그대로
curl -s -X POST https://fapi.daisomall.co.kr/ms/msg/selStr \
  -H 'Content-Type: application/json' -H 'Referer: https://www.daisomall.co.kr/' \
  -d '{"keyword":"서울","srchBassPkupStrYn":"Y","geolocationAgrYn":"N","currentPage":1,"pageSize":300,"srchYn":"Y"}'
```

올리브영은 공개 API가 없고 알려진 `.do` 경로는 WAF가 막거나 404다. 실제 매장찾기는 `https://www.oliveyoung.co.kr/store/store/getStoreInfoMain.do`이며 `#storeList`를 **서버 렌더링**한다. 페이지 자체 검색창(`#searchKeyword`)에 25개 자치구를 넣고 `li._openYStore`를 긁었다. `서울 중구`만 0건을 돌려주어 명동·을지로·충무로 등 랜드마크 키워드로 보충했다. 중복 제거 키는 `getStockStoreDetail('CODE', …)`의 매장 코드다.

> 검색 기반 수집은 이번 사고의 원인이기도 하다. 366이 명부 전체라는 보장은 없다. 더 올라갈 수는 있어도 내려가지는 않는다 — **누락 138은 하한이다.**
