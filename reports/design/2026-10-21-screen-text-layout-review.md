# 예약 화면 문장·레이아웃·버튼 전수 점검 (2026-10-21~22)

요청: "문장이 어색하게 줄바꿈 되는 화면, 텍스트가 레이아웃을 벗어나는 화면, 버튼을 눌렀을 때 동작이 제대로 안 되는 화면을 모두 검토."
대상: 업체 관리자(`/partner/*`)와 고객 예약 흐름. 기능 브랜치 `codex/service-quality-release-20261018`(HEAD `e608426`) 위의 작업 트리, 로컬 Supabase QA 스택(54381/54382)과 테스트 매장 `myseouldrop-booking-studio`.

## 1. 결론

- **관리자에서 확인된 결함은 모두 고쳤습니다.** 한국어 어절 중간 줄바꿈 86곳, 버튼·탭이 좁은 칸에서 접히거나 겹침, 글자 잘림·삐져나옴이 대상입니다. 버튼 결함 2건(휴대폰 정산 표 이름 링크를 누를 수 없음, '시간 변경' 창의 잘못된 오류)도 고쳤습니다.
- **고객 쪽 결함도 모두 고쳤습니다.** 프랑스어 가격 '₩60000', 일본어·중국어·영어의 1~2글자 마지막 줄, 320px 지도 버튼 2줄, 36px 버튼이 대상입니다.
- **재측정 결과:** 수정 후 22개 화면 크기·언어 조합을 다시 재서 넘침·잘림·겹침·어절 중간 줄바꿈·가려진 버튼 0건을 확인했습니다. 남은 것은 의도된 말줄임과 아래 §5뿐입니다.
- **실제 흐름:** 버튼을 직접 누르는 흐름 점검 6종이 모두 통과했습니다. 예약 확정 16/16, 고객↔업체 왕복 22/22(수정 후 B 13/13), 전화 예약 10/10, 설정 저장 왕복 29/29, 긴 값 14/14 중 의미 있는 실패 0입니다.
- **Codex 리뷰:** 8차 7점 → 9차 8점(남은 P3 1건) → 10차 9점(새 결함 없음).

## 4. 버튼 동작 결과

**크롤러 결과**
- **고객:** 영어 1440·390, 프랑스어 360에서 각 68개 컨트롤 모두 정상입니다. 프랑스어 'Articles' 1건은 크롤러 타이밍 문제였고, 영어에서는 같은 링크가 정상이었습니다.
- **관리자:** 1440·390 모든 화면과 예약 상세·캘린더 상세·대화·예약 추가·시간 변경·예약 취소 창·더보기 메뉴를 확인했습니다. 실제 결함은 §3-14 한 건입니다.
- **나머지 '실패'의 원인:** React가 누르는 순간 다시 그려 data 속성이 사라진 경우, 또는 열린 시트 뒤의 배경 버튼을 누르려 한 경우였습니다. 다음은 따로 눌러서 정상임을 확인했습니다.
  - 홈 '접수 준비'의 설정·확인 버튼 4개
  - 정산 이름 링크(휴대폰은 수정 후 탭하면 예약으로 이동)
  - 매장 정보 스위치

**실제 흐름(로컬 테스트 매장, 끝나면 원래대로 정리)**
- **예약 확정:** 고객 요청 → 관리자 '예약 확정'(확인 창 "예약 확정할까요?") → 고객 Confirmed → '메시지'로 해당 대화 열림 → 업체 취소(사유 선택) → 고객 Cancelled → 홈 최근 변경. **16/16**
- **고객↔업체 왕복:** 요청 → 고객 메시지 → 관리자 답장 → 시간 변경 → 고객 목록 반영 → 고객 취소. **22/22**, 시간 변경 수정 후 B 부분 **13/13**
- **전화 예약:** 예약 추가 → 캘린더 → 휴대폰 터치(쓸기·길게 눌러 끌기) → 업체 취소. **10/10**
- **설정 저장 왕복:** 예약 설정·매장 정보(임시 안내·영어 응대)·메뉴 설명·월요일 근무시간을 바꿔 저장하고, 새로고침으로 반영을 확인한 뒤 원복했습니다. '변경사항 버리고 다시 불러오기'와 '되돌리기'도 확인했습니다. **29/29**
- **긴 값:** 6개 화면 × 360·1440 측정 후 정리했습니다. 남은 3px은 메모 칸 줄 끝의 보존 공백(보이지 않음)입니다.

## 5. 남은 것(고치지 않음)

- **브라우저 기본 확인창:** '변경사항 버리고 다시 불러오기'는 `confirm()`을 씁니다. 동작은 정상이지만 다른 확인 창(예약 확정·취소)과 모양이 다르고, 일부 내장 브라우저에서는 막힐 수 있습니다.
- **오래 걸린 요청 1건:** 측정 부하가 가장 심할 때 `/api/partner` 요청 하나가 17분 걸린 뒤 503으로 끝났습니다. 재현은 안 됐지만, 데이터 요청에 시간 제한이 있는지 서버 쪽 확인이 필요합니다.
- **스위치 크기:** 매장 정보 스위치는 보이는 크기 44×26이고, 누르는 영역만 넓혔습니다.
- **1024px 비터치 측정:** 작은 링크가 16군데로 잡힙니다. 마우스 화면 기준이고, 실제 iPad 가로 화면(터치)에서는 44px 규칙이 적용됩니다.
- **의도된 말줄임:** 메시지 미리보기, 캘린더 월 보기 예약 이름, 장소 목록 이름.
- **클래스 충돌 위험:** 고객 앱 전역 클래스(`.topbar`)가 관리자에 걸린 것은 `.overlay` 때와 같은 계열입니다. 관리자 셸에서 일반 이름(`.toolbar`, `.panel`, `.tabs`…)을 새로 만들 때는 고객 앱 전역 규칙과 겹치는지 확인해야 합니다.
