# 예약 관리자 UX 벤치마크

조사일: 2026-10-19 · 공개 공식 자료 기준 · 실제 업체 데이터 변경 없음

## 결론

현재 관리자는 기능이 없는 것만이 문제가 아니다. **업무 단위가 아니라 저장 데이터 구조대로 입력을 나열한 것**이 가장 큰 사용성 문제다. 업체가 생각하는 일은 ‘다음 화요일에 쉬기’, ‘이 선생님에게 이 메뉴 연결하기’, ‘오늘 예약 확인하기’다. 현재 화면은 긴 폼과 반복 행을 조립해야 이 일을 할 수 있다.

재설계는 예약 처리와 운영 설정을 분리하고, **대상 선택 → 현재 상태 확인 → 필요한 부분만 변경 → 저장 결과 확인**으로 통일한다. 아래 비교에서 도출한 자체 설계 제안이며, 경쟁사의 화면을 복제하는 안이 아니다.

## 2. 제품별 관찰 → 우리 서비스에 적용

### 마메드네 — 현장 일정 관리

공식 디자이너 앱은 온·오프라인 예약 확인, 예약 금지, 모바일 일정 관리를 안내한다. 게시 스크린샷은 날짜와 시간표를 중심으로 작업을 시작하는 구조다. 메뉴와 스타일의 연결도 설명하지만, 사업자 웹 관리자 내부의 저장 방식이나 충돌 처리까지 확인할 수는 없었다. [공식 앱 안내](https://play.google.com/store/apps/details?hl=ko&id=com.kakao.beauty.hairshop.designer)

**적용:** 예약 가능 시간을 숫자 배열이 아니라 일정으로 보여주고, 대상 담당자와 날짜를 먼저 선택하게 한다. 모바일은 긴 설정 폼보다 당일 목록과 날짜별 차단을 우선한다.

**보류:** 오프라인 예약 입력·CRM·스타일북을 즉시 추가하지 않는다. 현재 승인 범위와 데이터 계약이 없다. 선결제 비율이나 환불 정책도 경쟁사 값을 가져오지 않는다.

### 카카오비즈니스 매장관리 — 반복 규칙과 예외

공식 가이드는 같은 시간을 적용할 요일을 묶어 선택하고, 영업일/휴무일과 휴게시간을 구분한다. 특정 기간의 임시 영업시간은 평소 요일 규칙보다 우선하며, 날짜 지정 휴무와 등록·변경 이력을 별도로 설명한다. [매장관리 가이드](https://kakaobusiness.gitbook.io/main/channel/run/mystore)

**적용:** ‘매주 반복’과 ‘특정 날짜’를 탭으로 분리한다. 평일/주말/선택 요일 복사, 하루 휴무, 일부 시간 차단을 제공한다. 변경한 대상·날짜·적용 결과를 명시한다.

**그대로 가져오지 않음:** 공휴일 자동 계산·매월 n번째 휴무는 우리 서버가 지원하는 규칙으로 검증하기 전에는 노출하지 않는다. 매장 사진·주소 편집은 플랫폼 운영팀 책임을 유지한다. 지도용 변동 가격은 확정 가격이 필요한 예약 상품에 그대로 쓰지 않는다.

### 네이버 스마트플레이스 — 상품과 공개 조건

뷰티형 가이드는 상품의 기본정보와 일정설정을 구분하며 새 상품이 바로 노출되는 것은 아니라고 안내한다. 상품별 일정/재고가 독립적이라는 제약도 명시한다. 예약금 안내는 시술금액과 예약금 설정을 구별한다. [상품·일정](https://help.naver.com/service/30026/contents/20694?lang=ko&osType=COMMONOS), [예약금](https://help.naver.com/service/30026/contents/20691?lang=ko&osType=COMMONOS)

**적용:** 메뉴 목록에서 총 가격·소요시간·제공 담당자·판매 상태를 함께 보여준다. ‘저장됨’과 ‘고객 예약 가능’을 다른 상태로 다룬다. 예약금이 있으면 무료처럼 표시하지 않는다.

**반대로 설계:** 상품마다 독립된 시간표나 재고를 만들어 중복 예약 위험을 넘기지 않는다. 우리 서비스는 매장 수용량과 담당자 점유를 공유하는 기존 승인 모델을 유지한다.

### 토스플레이스 — 업무의 시작점과 상세 확인

현재 예약 가이드는 매장/담당자를 선택해 휴무·예약 시간을 설정하고, 예약 홈에서 일·주·월·목록으로 확인하는 흐름을 제공한다. 상품 가이드는 기본 정보 후 필요한 설정을 이어가며, 결제내역 가이드는 목록에서 선택한 건을 오른쪽 상세로 확인한다. [예약 설정](https://guide.tossplace.com/operate/booking-setup), [예약 처리](https://guide.tossplace.com/operate/manage-booking), [상품 등록](https://guide.tossplace.com/operate/register-product), [결제 상세](https://guide.tossplace.com/operate/view-payment-history)

**적용:** 예약의 기간/담당자 필터, 목록과 상세를 함께 보는 작업 공간, 명확한 한 가지 주 행동을 채택한다. 담당자 정보·제공 메뉴·근무시간은 탭으로 나눈다.

**그대로 가져오지 않음:** 수동 입금 확인 후 확정 방식이나 토스의 담당자 수 제한은 우리 정책으로 채택하지 않는다. 우리는 승인된 결제 검증 후 즉시 확정이라는 기존 방향을 유지한다.

## 4. 접근 비교와 결정

1. **현재 폼만 정리:** 가장 빠르지만 일정 조립과 저장 범위 혼란은 남는다.
2. **운영 작업 공간 — 권장:** 탐색/목록/상세를 분리하고 반복 일정 편집을 시각화한다. 현재 API의 인증·검증·버전 충돌 보호를 재사용할 수 있다.
3. **POS형 올인원:** 예약·CRM·매출·결제·광고를 한 화면에 통합한다. 미구현 업무와 개인정보·결제 범위를 크게 늘려 초기 출시 목적과 맞지 않는다.

2번을 제안한다. 앱의 일반 소개·이미지 관리 권한은 늘리지 않는다. 디자인 시안의 예약/담당자/메뉴 이름·건수는 모두 표시된 예시이고 실제 서비스에 입력하지 않는다.

## 5. 후속 검증

마메드네 로그인 후 매뉴얼은 적절한 사업자 계정이 제공되면 추가 확인한다. 지금 단계에서 ‘모든 관리자 화면 확인 완료’라고 주장하지 않는다. 시안 승인 후 업체 관리자에게 ‘메뉴 추가’, ‘담당 메뉴 연결’, ‘다음 화요일 휴무’, ‘오늘 예약 상세 확인’ 네 가지를 설명 없이 시켜 탐색 성공과 오류를 관찰한다. 현재 저장 API를 유지하는 개선부터 적용하고, 예약·결제 연동 전에는 가짜 통계로 채우지 않는다.

### 6.3 국내 관리자 대시보드 디자인 언어

- 사용자가 가리킨 Behance ‘Naver 부동산 Dashboard’(김희주, 2024, 개인 컨셉 — 네이버 공식 아님)를 이미지까지 확인: 연한 블루그레이 바탕 `#F4F6F9`, 흰 카드·테두리 없음·그림자 거의 없음·radius 12~16, KPI 4개를 한 카드 안에 hairline으로 분할(라벨 14 → 숫자 28 bold → 증감 칩 + 기준일), 라인/막대/도넛은 3~4색, 사이드바 흰색·활성 초록 틴트, 상태 칩은 틴트 배경. 12컬럼·거터 24·마진 40, 서체 NanumSquare.
- 교차 검증(당근 SEED 공식, 우아한형제들 셀프서비스 디자인시스템, 카카오비즈니스 파트너센터·스마트플레이스센터 앱 설명, TDS·KRDS 제3자 정리): 페이지 `#F2F4F6~#F4F6F9` / 카드 `#FFF` / 테두리 `#E5E8EB` / 그림자 없거나 `0 1px 2px 4%`, 그레이 10단계, 액센트 1색 + 의미색, Pretendard, 본문 14~15·제목 22~24·KPI 26~32, 4px 간격 베이스, radius 카드 12~16·입력 8·칩 full, 행 48~56px, 모든 정보를 카드 단위로, **조회와 편집 UI 분리**(배민).
- 홈 구성 공통: KPI 띠(전기 대비 증감) → 오늘 할 일/처리 대기(행마다 액션 1개) → 추이 차트 1장 + 랭킹 → 최근 리뷰·문의 피드 → 공지 카드. 피해야 할 것: 다크 네온·그라데이션, 거대 히어로 숫자, 카드 안 카드, 색 남용, 홈에 편집 폼.
