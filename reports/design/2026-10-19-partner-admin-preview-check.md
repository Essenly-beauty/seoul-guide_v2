# 관리자 UX 재설계 시안 확인 기록

2026-10-19 · 디자인 검토용 · 배포하지 않음

## 확인 위치

- 로컬 미리보기: http://127.0.0.1:3111/
- 시안 파일: `docs/designs/partner-admin-redesign-20261019/index.html`
- 조사: `reports/design/2026-10-19-partner-admin-benchmark.md`
- 제안 설계: `docs/superpowers/specs/2026-10-19-partner-admin-ux-redesign.md`

로컬 서버는 다음 명령으로 다시 실행할 수 있다. 다른 서버를 종료하지 않고, 포트 충돌 시 사용 중인 서버를 확인한다.

```sh
python3 -m http.server 3111 --bind 127.0.0.1 --directory docs/designs/partner-admin-redesign-20261019
```

시안의 내용은 브라우저 메모리에만 있고 새로고침하면 초기화된다. 업체/고객의 실제 데이터가 아니다. 예약 시스템이나 관리자 개선을 구현 완료한 결과물이 아니라 승인 전 인터랙션 시안이다. 저장 오류·권한·버전 충돌·고객 조회의 구현 검증은 별도로 해야 한다.

## 직접 브라우저에서 확인한 것

- 데스크톱의 사이드 탐색 / 대상 목록 / 일정 작업 공간 배치.
- 요일 복사 후 적용 버튼 활성, 변경 취소.
- 특정 날짜 선택, 하루 휴무 예시 적용, 예외 해제.
- 담당자 → 제공 메뉴 연결 예시 변경과 결과 표시.
- 담당자 근무 일정 탭 전환.
- 메뉴 가격 45,000→47,000원 예시 변경, 메뉴명 검색 후 변경 값 표시.
- 메뉴 화면 및 주간 일정 화면의 스크린샷을 도구 결과에서 확인했다. 파일 캡처는 보존하지 못했다.

## 코드 실행 검증

Node VM + 최소 DOM 스텁으로 시안 스크립트를 실행했다. 아래는 템플릿 로직 검증이며 실제 브라우저나 레이아웃 테스트를 대체하지 않는다.

- 7개 요일 행, 31개 날짜 렌더.
- 담당자 메뉴 연결 목록 렌더.
- 메뉴 검색 결과 제한.
- 연동 전 안내에는 가상 예약 상세 미노출, 연동 후 예시에만 실제 예약 아님 표시 및 잔액 표시.
- 외부 쓰기 API 호출(fetch/XHR/beacon/WebSocket) 없음.
- JavaScript 구문 검사 통과. 새 파일들의 공백 검사에서 오류 메시지 없음.
- 로컬 미리보기 HTTP 200.

## 미완료 확인 (2026-10-19 오전 기준, 아래 추가 검증으로 대부분 해소)

이후 브라우저 연결이 끊겨 사용 가능한 브라우저 목록이 비었다. 다른 제어 수단으로 우회하지 않았다.

## 추가 브라우저 검증 (2026-10-19, Playwright Chromium 헤드리스)

390×844(모바일·터치), 1024×768, 1440×900에서 시안을 직접 조작해 확인했다. 판정은 스크립트 단언 + 스크린샷 육안 확인.

통과한 것
- 모든 화면(예약 현황 현재/연동 후, 메뉴, 담당자 3개 탭, 일정 매주 반복/특정 날짜, 예약 설정)에서 가로 넘침 없음(`scrollWidth == clientWidth`), 콘솔·페이지 오류 0.
- 모바일 요일 편집 패널, 특정 날짜 31칸(칸 43×44px), 일부 시간 차단 예외 추가→해제.
- 예약 연동 전 → 연동 후 예시 → 다시 연동 전 전환. 연동 전에는 예약 행 0개, 연동 후 3개. 예약 C 선택 시 상세 총액 150,000원·현장 잔액 140,000원 일치.
- 데스크톱 1440에서 예약 목록/상세 나란히, 1024와 모바일에서는 위아래 배치.
- 고객 예약 화면 대화상자: 모바일에서 화면 안에 들어오고 내부 스크롤 불필요, 14:00 선택 표시, 13:00 비활성, ‘흐름 확인 완료’와 Esc로 닫힘.
- 모바일 ‘더보기’ 팝오버 열림 → 예약 설정 이동 후 자동 닫힘. 예약 현황 체크리스트의 ‘설정 확인’ 이동.

발견 후 시안에서 수정한 것
- 예약 목록의 ‘확정’ 배지가 행 높이만큼 세로로 늘어남 → 위쪽 정렬(배지 높이 26px).
- 메뉴 이동 시 `main.focus()`가 페이지를 115px 내려 상단 바(고객 예약 화면 보기·접수 상태)가 가려짐 → 맨 위로 이동 후 스크롤 없이 포커스.
- 모바일에서 변경이 없어도 저장 영역이 하단에 고정돼 약 100px를 차지(첫 화면에 요일 1개만 보임) → 변경이 있을 때만 고정. 담당자 기본정보 입력 시에도 고정 전환. 첫 화면 요일 2개.
- 모바일 알림이 화면 중간(하단 160px)에 떠 목록·연결 버튼을 가림 → 하단 탐색과 고정 저장 영역 바로 위에 표시. 데스크톱도 고정 저장 영역 위로.
- 모바일 상단 ‘고객 예약 화면 보기’ 버튼 높이 40px → 44px.

여전히 미검증
- 실기기(iOS Safari 안전 영역 포함)와 화면 낭독기, 키보드만으로의 전체 동선, 자동 대비 검사.
- 마메드네 사업자 로그인 내부 매뉴얼: 미확인. 현재 공식 파트너스/공식 앱 설명과 게시 이미지까지만 확인했다.

앱 소스, 운영 DB, 권한, 결제, 배포 설정은 변경하지 않았다. 새 `docs/` 파일은 기존 저장소의 ignore 정책에 포함되므로 향후 커밋 시 이 시안·설계 파일을 의도적으로 포함할지 검토해야 한다. 기존 사용자 작업 `reports/operations/service-quality-release-2026-10-18.md`는 변경하지 않았다.

## 예약 캘린더 개편 검증 (2026-10-19 오후)

사용자 요청(구글 캘린더 느낌, 시간·담당자·예약자 정보 한눈에, 빈 시간에서 예약 추가와 시간 막기·휴무 둘 다, 헤어샵 디자이너 선택)에 따라 ‘예약 현황’과 ‘예약 가능 일정’을 ‘예약 캘린더’로 합치고 고객 미리보기에 디자이너 선택을 넣었다. Playwright 헤드리스로 68개 단언 통과(1440×900, 1024×768, 390×844 터치).

- 일간: 디자이너 3열, 10/19 예시 예약 5건, 휴게 3구간(매장·담당자 중복 휴게는 한 구간으로 합침), 막은 시간 1건, 현재 시각 선. 14:00 시그니처 펌 블록 위치·높이(정리 15분 포함) 계산 일치.
- 예약 상세: 고객·경로(“고객이 지우 디자이너를 직접 선택”)·총액 150,000원·예약금 10,000원·잔액 140,000원, 열면 제목으로 포커스 이동.
- 빈 칸 → 예약 추가: 디자이너·시간 자동 채움, 디자이너별 메뉴만 노출(디자이너 바꾸면 다시 거름), 종료 시각 자동 계산, 기존 예약과 겹치면 추가 불가, 근무시간 밖은 경고 후 허용, 추가 후 블록·상세 표시.
- 시간 막기·휴무: 막은 시간 추가, 예약 2건 있는 디자이너 휴무 시 경고 후 하루 빗금 처리·기존 예약 유지. Esc로 선택지 닫힘. 디자이너 칩으로 열 거르기.
- 주간: 7열, 화요일 정기 휴무 빗금과 머리 ‘휴무’, 예약 14건, 날짜 머리 → 일간 이동. 주간에는 오른쪽 요약을 접어 칸을 넓히고 겹친 예약은 시작 시각·이름만.
- 현재 제공 범위: 예약 블록 0, ‘예약 추가’ 비활성.
- 고객 미리보기: 담당자 선택형 4단계, 시그니처 펌 → 디자이너 2명(지우·소연)과 각자 가장 빠른 시간, 소연 선택 → 가능한 시간만 표시 → 확인 → ‘시안 예약 넣어 보기’로 캘린더 소연 열에 앱 예약 생성·상세 표시. 매장 예약형으로 바꾸면 3단계(디자이너 단계 없음)·캘린더 단일 ‘매장 예약’ 열.
- 태블릿: 상세는 오른쪽 시트+배경, 배경 누르면 닫힘. 모바일: 목록 6항목, + 버튼은 하단 탐색 위, 선택지·입력은 아래 시트, 추가 후 목록 7항목, 타임라인 1열·디자이너 전환. 모든 크기 가로 넘침 없음, 44px 미만 터치 대상 없음, 콘솔 오류 0.

남은 것: 실기기·화면 낭독기·키보드 전체 동선 미검증. 업체 입력 예약을 근무시간 밖에 허용할지는 정책 질문으로 남김. 실제 앱의 예약 저장·고객 예약 화면 디자이너 단계는 미구현.

## 홈·예약 목록·고객·통계 추가 검증 (2026-10-19 오후, 시안 v3)

2차 조사(벤치마크 6절) 반영. 시각 토큰을 국내 대시보드 문법(흰 카드·hairline·radius 14·Pretendard·tabular 숫자)으로 바꾸고 홈/예약 목록/고객/통계/알림 설정을 추가했다. Playwright 헤드리스 1440×900·1024×768·390×844에서 **신규 58개 + 기존 캘린더 68개 = 126개 단언 통과**, 콘솔 오류 0, 가로 넘침 0, 모바일 44px 미만 터치 대상 0.

- 홈: KPI 4개(오늘 예약 5건 ▲3 지난주 월요일 2건, 방문 완료 1, 노쇼 0, 현장 결제 예정 370,000원), 할 일(노쇼 이력 고객 2명·10/27 매장 휴무·연동 상태), 이번 주 13건·지난주 11건 막대 7개, 디자이너별 3행, 다음 예약 3건(11:30부터), 접수 준비 3/4, 최근 활동 6건. KPI ‘방문 완료’ 클릭 → 예약 목록 오늘+방문 완료 탭 1건.
- 예약 목록: 이번 주 13건, 10월 탭 건수 전체 38/확정 12/방문 완료 22/노쇼 2/취소 2, 디자이너 필터(지우 15건), 검색 ‘강다은’ 3건(입력 포커스 유지). 상세: 예약번호 R3, 시작 전이라 노쇼 비활성. 취소 → 사유 선택 필수 + 예약금 환불 안내 → ‘취소됨 · 매장 사정으로 취소’, 취소 탭 1. 시간 변경 폼(11:30 → 12:30, 자기 자신과 충돌 없음) → 상세 12:30–13:30. 네이티브 confirm 0회.
- 고객: 예약 상세 이름 → 고객 패널(이서연 방문 2회). 목록 12명 최근 방문순(김하늘 단골 첫 행), 노쇼순 정렬, 검색 ‘박지민’ → 상세 노쇼 1회·예약·방문 이력 3건·메모 저장·‘이 고객 예약 추가’로 캘린더 폼에 이름/연락처/주 담당(민서) 자동 채움.
- 시간 막기 매주 반복: 매장 전체 월 18–19시 → 10/19 모든 디자이너 열에 표시, 주간 보기 다음 주 26일(월)에 표시·27일(화) 없음, 상세 ‘매주 월요일’.
- 통계: 10월 KPI 4개, 카드 4개(디자이너별·메뉴별·경로·시작 시간대), 이번 주 전환. 예약 설정 알림 토글 3개.
- ‘현재 제공 범위’: 홈 KPI ‘—’, 최근 활동 비어 있음, 통계는 ‘예약 연동 후 집계돼요’ 안내만.

발견·수정: 활동 피드 점과 막대 세그먼트에 쓴 클래스 `app`이 루트 레이아웃 클래스 `.app`과 충돌해 세로로 늘어남(`k-`/`s-` 접두사로 분리). 모바일 기간 세그먼트 세로 줄바꿈, 모바일 예약 행 과다 높이, 시작 시간대 0건 막대, ‘다음 예약’ 상대 시간(‘2시간 50분 후’ → ‘3시간 후’).

미검증: 실기기·화면 낭독기·키보드 전체 동선, 다크 모드, 1,000건 이상 목록 성능. 업체별 고객 보관 정책(기간·마스킹)은 운영팀 결정 사항.

## 담당자 아바타·끌어서 옮기기 추가 검증 (2026-10-19 오후, 시안 v3.1)

사용자 요청: 캘린더 열 머리에 담당자 원형 사진 + 이름, 구글 캘린더처럼 드래그로 시간 변경.
