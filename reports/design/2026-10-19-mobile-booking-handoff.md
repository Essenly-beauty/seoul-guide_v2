# 영문 모바일 예약 · 지도 반영 기록

기준: c66c5db / `codex/service-quality-release-20261018`. 배포나 GitHub push는 수행하지 않았다.

## 실제 웹앱에 반영한 코드

- 기존 `/map`의 검색창, 하단 패널, 지도 버튼에 단계별 그림자를 적용. 선택된 일반 매장 핀은 오렌지 바탕·흰 아이콘으로 표시한다. 올리브영 고유 마크와 지도·지하철·좌표 그룹 동작은 유지한다.
- 오렌지는 기존 브랜드 #e94f00를 유지하면서 작은 흰 글씨가 올라가는 행동 요소에 #c94300를 사용한다(대비 약 4.90:1).
- 장소 상세 Services에 업체가 입력한 영문 메뉴·설명·가격·소요 시간을 읽는 UI를 연결했다. 로딩·오류·재시도·미등록 상태를 구분하고 원래 외부 출처 링크를 유지한다.
- `GET /api/places/[id]/catalog`: 알려진 장소만 허용, 안전한 공개 데이터만 반환, no-store. DB 오류는 빈 메뉴 대신 503으로 처리한다. 개인정보·내부 메모·회원 권한·운영 일정·예약금 정책은 반환하지 않는다.
- DB에는 플랫폼 소유 `merchant_publications`와 공개용 `published_merchant_catalogs`를 추가하는 마이그레이션을 작성했다. 활성 매장·승인된 장소 연결·공개 카테고리/메뉴·완성된 영문 정보·가격/시간이 있어야 노출한다. 비공개/휴업 전환과 수정/삭제도 공개 데이터에 반영된다.
- **운영 DB에는 적용하지 않았다. 승인된 실제 매장↔장소 매핑도 생성하지 않았다.** 배포 전 마이그레이션, 실제 매핑 확인 및 운영 검증이 필요하다. `booking_enabled=false`는 유지한다.

## 디자인 확인용 시안

`docs/designs/customer-booking-mobile-20261019/index.html`

로컬 주소: http://127.0.0.1:3112/

영문 모바일 우선: 지도 → 메뉴 → 담당자 → 날짜/시간 → 최종 확인 → 완료 예시 → 예약 목록 → 취소 예시. PC 왼쪽 목록에서 각 화면으로 바로 이동할 수 있다. 메뉴/담당자 변경 시 이전 시간 선택을 지우고, 최종 화면에 담당자·종료 시간·서울 시간·총액/예약금/잔액을 함께 표시한다. 휴무일·빈 시간대·선택 만료·저장·취소 후 상태도 포함했다.

이 흐름과 숫자 가격 핀은 **별도 디자인 시안**이다. 실제 앱의 예약 화면/결제 API로 연결한 상태가 아니다. 시안은 네트워크 호출, 예약 저장, 시간 점유, 결제, 메시지 전송을 하지 않는다. 서비스 가격·담당자·가용 시간·예약금 1만원은 검토용 예시다. 정책을 확정한 것으로 간주하지 않는다.

## 검증

- 앱 전체: 143개 테스트 파일 / 1,940개 테스트 통과(새 메뉴 경계/API/화면 상태 25개 포함).
- 타입 검사, ESLint 통과. Next lint 폐기 예정 안내와 다중 lockfile 안내는 기존 환경 경고.
- 독립 로컬 PostgreSQL QA DB에서 35개 확인 통과. 새 테이블/함수/데이터는 하나의 트랜잭션에 적용 후 모두 ROLLBACK. 익명·로그인 사용자 읽기/쓰기 권한, 공개 해제, 영문 공백, 값 갱신, 다른 매장 분리를 확인했다.
- 시안 상태/라우팅/키보드 포커스/로컬 경로 15개 Node VM 확인. CSS 3개 파싱 통과, JS syntax, diff 공백 확인 통과.
- 별도 코드 리뷰 후 선택 시 포커스 유실, 취소한 예약의 과거 확인 화면 재진입, 라이트 모드 패널 그림자 우선순위를 수정했다.
- **배포 빌드 미통과:** 기존 `next/font`가 fonts.googleapis.com에 접근할 때 ENOTFOUND. 폰트를 임의 대체하거나 성공으로 처리하지 않았다.
- **브라우저 렌더링/새 스크린샷/모바일 실기기 확인은 미완료.** 이 VSCode 런타임의 브라우저 연결이 제공되지 않았다. 사용자 제공 캡처로 가격 핀 선호는 확인했다. BeautyNow의 영문 모바일 화면을 직접 검사했다고 주장하지 않는다. `/en` 웹 조회도 cache miss였다.

## 다음 실제 연결 순서

1. 현재 시안의 디자인을 기존 앱 컴포넌트로 옮기면서, 승인된 공개 메뉴 가격으로 지도 `From` 핀과 장소 상세를 일치시킨다. 실제 매장 매핑 확인이 필요하다.
2. 담당자 영문 이름/소개 저장, 공개 담당자 조회, 기존 일정 규칙을 이용한 슬롯 API를 연결한다. 거래·임시 점유 없이 계산된 슬롯은 예약 가능 보장이 아님을 유지한다.
3. 예약/슬롯 점유를 DB 트랜잭션으로 저장하고 중복 요청·동시 예약·만료 복구를 검증한다. 고객/업체는 동일한 예약 기록을 읽어야 한다.
4. 돈의 흐름·수수료·환불 정책·PG가 확정되면 결제/webhook/취소/환불/정산을 연결한다. 결제 통합 검색은 네트워크 실패로 공급자를 선택하거나 설치하지 않았다.

## 운영 적용 주의점

마이그레이션 파일: `supabase/migrations/20261019140243_public_merchant_catalog.sql`.

배포 순서: DB 마이그레이션 검증/적용 → 플랫폼 담당자가 실제 merchant UUID와 기존 place ID의 소유·매장 일치를 확인 → platform/service role로 공개 연결 승인 → 익명 조회와 비공개 전환을 운영 환경에서 확인 → 앱 배포. 이름 유사도로 자동 연결하지 않는다. 일반 업체 계정은 연결 승인/변경이나 공개용 테이블 쓰기 권한이 없다.

`CATALOG_TEST_DB_PORT=54362 node scripts/test-public-catalog-db.cjs`는 이 세션의 독립 로컬 QA DB에서 실행한 명령이다. 다른 환경에서는 준비된 독립 QA DB 포트를 명시해야 한다. 운영 DB URL을 받지 않고 loopback에만 연결하며 기본 5432/54322 포트는 거부한다.

## 후속 사용자 확정: 기존 고객 앱 전체 공통 테마

이 절은 앞의 오렌지 주 행동/선택 핀 설명을 대체한다.

- **블랙 기본:** 주요 버튼, 날짜/시간 선택, 하단 탭, 필터, 지도 선택 핀. 다크 모드는 밝은 중립색으로 반전해 대비 유지.
- **오렌지 포인트:** 체크박스/라디오, 완료·혜택 등 작은 상태 강조. 큰 주황 면적과 주황 그림자는 제거.
- **여유 있는 구조:** 고객 화면은 좌우22px(좁은 화면18px), 주요 섹션24px, 목록 위아래18px. 제목/본문은 산세리프, 기술적인 대문자 화면 제목을 일반 제목으로 변경. 카드의 상시 그림자를 줄이고 지도/시트에 집중.
- **담당자 행:** 50px 원형 이니셜, 이름/직함 상단 정렬, 언어 칩을 작은 설명으로 전환, 선택 원을 이름 높이에 정렬. 실제 담당자 사진을 새로 만들어 넣지는 않았다.
- **기존 앱 연결:** app/customer-theme.css를 app/layout.tsx에서 globals.css 다음에 import. /map, /search, /place, /favorites, /menu, /ranking 등 공통 UI에 적용. /design에 action 토큰 추가. data-partner-shell로 업체 관리자 제외.
- **실제 앱 로컬 주소:** http://127.0.0.1:3113/map (현재 작업 worktree). 루트 checkout의3100 서버와 별개. 앱의 실제 라우트/컴포넌트로 실행하며, 인증/저장은 기존 독립 QA Supabase에 연결한다. 운영 환경은 변경하지 않았다. 로컬 실행 스크립트: /private/tmp/run-customer-theme-preview.cjs (키는 프로세스 환경으로만 전달, 파일에 저장하지 않음).
- **시안 주소:** http://127.0.0.1:3112/#staff. 전체 예약은 계속 별도 시안이며 거래 기능을 활성화하지 않았다.

검증: 전체1,940 테스트 통과, 타입 검사/린트 통과, 시안 VM15 및 CSS 파싱/공백 확인 통과. 별도 리뷰에서 다이소 카테고리의 안쪽 칩 주황색과 바깥 블랙 선택색의 충돌을 발견해 안쪽까지 동일한 action/on-action 토큰으로 수정했다.

HTTP 확인: /map, /search, /favorites, /menu, /ranking, /design, /partner 모두200. 실제 응답 CSS에 새 테마가 기본 CSS 뒤에 포함됨을 확인했다. /partner 응답의 제외 표식도 확인했다. 이는 브라우저 렌더링/상호작용 확인과 다르다.

실행 중 환경 문제: 초기 로컬 앱은 QA 환경 변수 미설정으로500이었으나 기존 로컬 Supabase 설정을 메모리로 주입해200으로 복구. 파일 감시 제한은 polling으로 전환. 개발 서버 시작 시 생성 타입을 다시 쓰면서 tsc가 실패한 뒤, next typegen으로 타입을 재생성하고 타입 검사/린트 통과를 확인했다. Google Fonts 다운로드 제한은 남아 있어 로컬 앱에서 대체 서체가 사용될 수 있으며 운영 빌드/새 브라우저 스크린샷은 여전히 미확인이다.
