Codex가 10/19 밤부터 10/20 오후까지 같은 작업 트리에서 시안 v3.4를 실제 `/partner/*`에 연결했다(`reports/operations/2026-10-20-dashboard-demo-parity.md`). 그 보고서는 PC·모바일 실제 화면 비교와 터치 검증을 “미완료”로 남겼다(연결된 Chrome이 정책 확인 실패로 로컬 페이지를 열지 못함). 이 문서는 그 빈칸을 Playwright 헤드리스 Chromium으로 채운 기록이다. 코드는 고치지 않았고, 결함은 아래 목록으로만 남긴다.

- 비교 기준: 시안 `docs/designs/partner-admin-redesign-20261019/index.html` v3.4(3111)와 그 검증 스크린샷.

## 3. 흐름 점검 기록

1. **전화 예약 추가** (예약 목록 › + 예약 추가): 전화/방문 → 고객 이름 → 연락처 → 메뉴(‘Signature cut · 60분 · 60,000원’) → 담당자(Min/Jiyoon) → 날짜 10/21 → 가능 시간이 ‘조회 중…’ 뒤 목록으로 바뀜 → 11:00 선택 → 저장. 모달이 닫히고 목록 ‘이번 주’에 ‘10월 21일 (수) 11:00–12:00 화면점검 테스트 · 전화 · 60,000원 · 현장 결제 · 예약 확정’이 뜬다. 시안의 전화 예약 폼과 항목이 같다.
2. **캘린더**: 10/21 일 보기에서 Min 열 11:00–12:00 블록 + ‘정리’ 15분 띠. 오른쪽 요약 ‘예약 확정 1건 · 취소 1건’. 블록 클릭 → 상세 패널(일시·정리 포함 12:15까지·메뉴·담당자·요청사항·총 시술금액·예약금 없음·결제 방식 현장 결제·예약 취소/시간 변경/메시지·예약 기록). 시안의 상세 패널과 항목 순서가 같다.
3. **모바일 터치** (CDP 터치 이벤트): 블록을 `scrollIntoView` 한 뒤 (a) 바로 25px×6 위로 쓸기 → 캘린더 내부 스크롤 42→390, 이동 안내 없음. (b) 0.7초 누르고 있기 → ‘이동할 시간을 선택한 후 변경 내용을 확인해 주세요’ → 12px×8 아래로 끌기 → ‘10월 21일 (수) 11:30로 이동 · 놓은 뒤 확인’, 스크롤 고정 → 놓음 → ‘변경 확정’/‘닫기’ 버튼. ‘닫기’로 되돌렸다(예약 시간은 11:00 그대로). Codex 보고서의 미검증 항목이 헤드리스 기준으로 확인됐다. 실제 iOS Safari 확인은 남아 있다.
4. **업체 취소**: 상세 › 예약 취소 → 모달 ‘예약 취소할까요?’(취소 사유 select: 매장 사정/고객 요청/중복 예약/기타) → 확정 → 상태 ‘취소’, 목록 요약 ‘취소 2건’. 시안의 취소 사유 필수 규칙과 같다.

## 5. 하지 못한 것

- 고객 앱 예약 흐름(`/place/myseouldrop-booking-studio/book`)과 메시지 대화(앱 예약이 없음), 사진 업로드, 검수 요청·취소, 담당자·메뉴 편집 저장은 열어보지 않았다. Codex의 HTTP 검증(90+43+45개)이 다루는 영역이다.
- 실제 기기(iOS Safari·Android Chrome) 터치, 프로덕션 빌드(Google Fonts DNS 실패 미해결), 원격 DB.
- 결함 수정. 같은 트리에서 Codex 세션이 작업 중이라 코드는 손대지 않았다. 수정 후 `impl-screens.cjs`·`impl-flow.cjs`를 다시 돌리면 된다.
