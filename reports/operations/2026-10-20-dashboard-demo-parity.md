기준일: 2026-10-20. 작업 위치: `.worktrees/service-quality-20261018`.

사용자가 지정한 별도 관리자 시안 `docs/designs/partner-admin-redesign-20261019/index.html`(v3.4, 3111)을 실제 파트너 화면의 기준으로 적용했다. 고객 예약은 `docs/designs/customer-booking-mobile-20261019`(3112)의 모바일 시안을 기준으로 적용했다. 실제 인증·저장·공개 데이터 조회는 모두 **3113의 MYSEOULDROP 웹앱**을 사용한다.

## 고객 서비스에 반영되는 데이터

- 메뉴 가격·소요 시간·공개 상태, 담당자·제공 메뉴·근무시간, 휴무·차단은 공개 카탈로그와 예약 가능 시간에 반영한다. 고객 예약은 같은 DB에 저장되어 관리자에 표시된다.
- 연락처·영어 응대·공지사항은 즉시 반영한다. 매장 이름·주소·소개·매장 사진은 시안의 검수 구분에 따라 요청 상태로 저장하며 승인 전에는 공개값을 바꾸지 않는다.
- 메뉴·담당자 사진은 실제 파일을 저장하고 활성 상태의 공개 대상에만 노출한다. 사진은 비율을 보존하며, 매장 갤러리에서는 등록된 공개 사진 전체를 볼 수 있다.
- 고객 예약의 메뉴 → 담당자 → 날짜·시간 → 확인 → 결과, 내 예약, 취소 및 대화를 실제 API로 연결했다. 새로 만든 별도 데모 데이터로 성공 화면을 대신하지 않는다.
- 예약 화면은 표시 중 30초 및 포커스 복귀 시 조회한다. 저장 성공은 서버 응답 확인 후 표시한다. 예약 충돌·읽기 전용·계정 전환을 검증한다.

## 실패·복구 및 접근성 보완

- 예약 생성 요청의 UUID와 입력은 결과가 불명확할 때 보관한다. 내부 화면 이동으로 지우지 않으며, 동일 요청 재시도로 중복 생성을 방지한다.
- 제출 전 입력과 업체 메모·매장 설정 초안도 계정별 메모리 저장소와 이동 확인을 사용한다. 계정 전환 시 다른 사용자의 초안은 복원하지 않는다.
- 시간 차단 저장 응답이 끊긴 경우에는 실패로 단정해 다시 저장하지 않고, 실제 서버 상태 조회 전까지 편집 잠금을 유지한다.
- 상세 패널의 작은 화면 모달 전환, 키보드 포커스 순환·복귀, 비활성 fieldset 제외, 네이티브 summary 접근을 보완했다.
- 캘린더의 가로 스크롤, 주간 예외 시간, 자정까지의 정리 시간, 예약 겹침을 처리했다. 터치 이동은 길게 누른 뒤에만 시작하도록 구현했지만 이번 변경 후 실제 터치 검증은 남아 있다.

## 검증과 한계

- 실제 PostgreSQL: 150개 검사 통과.
- 동시성: 7개 시나리오, 28개 검사, 실제 잠금 대기 7건 확인.
- 실제 Next.js/Supabase HTTP 왕복: 예약 운영 90개, 매장 정보·영문 정보 43개, 실제 사진 업로드·다운로드·삭제 45개 통과.
- 관리자 13개 경로, 고객 예약 및 로그인 총 15개 경로 HTTP 200 확인. 이것은 브라우저 화면 검증을 대체하지 않는다.
- 최종 전체 단위 테스트·TypeScript·ESLint 결과는 아래 최종 검증 기록에 기재한다.
- 연결된 Chrome을 다시 찾았지만, `http://127.0.0.1:3113` 접근 시 브라우저 관리 정책 확인 실패로 차단되었다. 우회하지 않았으며, 이번 변경의 PC/모바일 실제 화면 비교와 단계별 스크린샷은 **미완료**다.
- 프로덕션 빌드는 이전 Google Fonts DNS 실패가 미해결이며 배포 성공으로 취급하지 않는다. 개발 서버에는 폰트 대체 표시가 발생할 수 있어 실제 디자인 확인 시 확인이 필요하다.

## 운영 정책과 출시 전 남은 항목

현재 결제 모드는 `pay_at_venue`다. 온라인 예약금·PG 승인·실제 환불·플랫폼 수수료 지급·세금계산서 발행은 연결하지 않았다. 따라서 시안의 1만원 예약금·10% 수수료·익월 10일 지급 샘플을 실제 거래처럼 표시하지 않는다. 정산의 온라인 수납은 실제 0원이며 정책은 ‘결정 전’으로 표시한다.

검수 요청은 실제로 저장되지만 운영팀의 승인·반려 처리 화면과 알림 운영 절차는 별도 출시 작업이다. 임의로 승인 처리하지 않았다. 사진이 없는 실제 매장의 사진을 만들어 등록하거나 타 업체 사진을 대신 사용하지 않았다.

로컬 DB에만 마이그레이션을 적용했다. 원격 DB·운영 서비스 배포·커밋·GitHub 푸시는 수행하지 않았다. 상세 API 계약과 로컬 검증 방법은 [백엔드 검증 기록](./2026-10-20-partner-operations.md)을 참고한다.
