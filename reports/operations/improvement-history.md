# MYSEOULDROP 운영 개선 이력

최종 갱신: 2026-10-04 (KST). 이 문서는 첫 100명 운영을 위한 **회원·비회원 서비스 개선 작업의 이력과 남은 일**을 한곳에서 추적한다. 상품 랭킹·이미지 제작의 실행 문서가 아니다. 새 사실을 확인하거나 운영에 반영할 때 날짜별 기록을 추가하고, 아래 상태와 완료 조건도 함께 갱신한다.

**상태 표기:** `확인`은 문제나 현황의 근거를 확인한 것, `로컬 준비`는 코드·문서가 이 작업공간에만 있는 것, `미리보기 검증`은 프로덕션과 분리된 Vercel 배포에서 확인한 것, `운영 검증`은 실제 프로덕션에서 확인한 것, `미착수`는 구현·검증을 하지 않은 것이다. 테스트 통과나 문서 작성만으로 운영 완료로 바꾸지 않는다.

## 확정된 서비스 방향

- 비회원도 장소 검색·상세·랭킹·길찾기·기기 내 저장을 이용한다. 다른 사람에게 보이는 리뷰를 게시할 때만 로그인을 요구한다.
- 공유목록은 만드는 사람과 받는 사람 모두 로그인한다. 링크를 받은 사람은 원래 링크로 돌아가며, 로그인하지 않아도 일반 지도 탐색은 계속할 수 있다.
- 첫 100명 단계는 회원 수 자체보다 장소 발견·저장·길찾기 과업이 가능한지, 정보가 정확한지, 막히는 지점이 무엇인지 확인하는 기간이다. 아직 홍보 전이며 주로 오너가 사용했다.
- 기존 오너 개인 계정을 임의로 테스트 계정으로 분류하거나 변경하지 않는다. 검증용으로 만든 별도 계정만 확인된 테스트 계정으로 제외한다.
- 상품 추천은 부가 기능이다. 상품 정보 갱신은 별도 작업으로 진행한다. 추천 범위는 뷰티 중심의 공식 상세에서 확인한 **단품**이며, 세트·옵션 추천은 제외한다. 상품 이미지 누끼·자동 갱신은 현재 운영 개선 범위에서 제외한다.

## 날짜별 진행 이력

### 2026-09-23: 운영 범위와 검증 기준 정리

- 비회원 핵심 기능과 공개 리뷰에만 로그인 요구하는 정책을 확정하고 [첫 100명 운영안](../first-100-users-operating-plan-2026-09-23.md)을 작성했다.
- 회원 현황을 개인정보 원문 없이 집계하는 읽기 전용 리포트, 초기 운영 지침과 빈 참여자·문의 장부를 준비했다. 운영 사용자 관찰이나 행동 계측이 시작됐다는 뜻은 아니다.
- 공식 매장 목록, 상품 랭킹, 외부 평점, 자체 리뷰를 서로 다른 출처·갱신 주기의 정보로 구분했다. 상품 추천·랭킹 세부 작업은 이 문서의 운영 배포 범위에 섞지 않는다.

### 2026-09-26: 계정·비회원·운영 위험 확인

- [가입·리뷰 실사용 점검](signup-review-live-verification-2026-09-26.md)에서 별도 테스트 계정의 가입/로그인, 회원 리뷰 공개 상태 변경, 비회원 공개 조회를 확인했다. 복구 이메일 수신은 확인했지만 복구 완료 전체 경로는 아직 확인하지 않았다.
- [비회원 동선 점검](guest-flow-verification-2026-09-26.md)에서 지도·검색·랭킹·기기 내 저장·Google 길찾기 웹 열림을 확인했다. 운영의 다이소 저장 상세 404와 DB 장소 ID 제한은 별도 결함으로 기록했다.
- [후속 운영 점검](remaining-operations-audit-2026-09-26.md)에서 공유목록 공개 SELECT(P0), 피드백/회신 경로 불명확, 불완전한 데이터 다운로드를 확인했다. 문제를 찾은 시점에 운영 수정이 완료된 것은 아니다.
- 공유목록 로그인 요구·원래 링크 복귀·오너 링크 관리 코드를 로컬 구현했고, 공개 SELECT를 막는 DB 마이그레이션과 역할별 테스트를 준비했다. 기존 공유 링크의 4개 장소 ID는 모두 현재 미게시 샘플이라 유효 링크도 표시 가능한 장소 0곳으로 안내한다. 내용을 임의로 재게시하거나 기존 링크를 삭제하지 않았다.
- 18:15 KST 읽기 전용 회원 집계를 재실행했다. 전체 6개 계정 중 확인된 테스트 계정 1개를 제외한 5개는 **실제 외부 이용자로 확인된 5명**이 아니다. `npm test` 104개 파일/1,007개 항목, 타입 검사, 린트, `git diff --check`는 통과했다. pgTAP은 Docker 데몬이 없어 실행하지 못했고 브라우저 자동 E2E도 환경 제약으로 미완료다.
- 배포 사전 점검에서 로컬/원격 이력 분기와 다수의 미커밋 변경, Supabase CLI 인증 부재, Vercel CLI 프로젝트 조회 오류를 확인했다. 이번 이력 작성 시점까지 공유목록 앱/DB 마이그레이션을 운영에 적용하거나 푸시하지 않았다.

### 2026-09-27: 랭킹 후속 작업 보류 및 운영 우선순위 재확인

- 공식몰 순위의 Google 시트 1회 입력 시험은 [별도 랭킹 운영 기록](ranking-google-sheet-operations-2026-09-26.md)에 결과와 후속 조건을 남기고 오너 요청에 따라 다음 작업으로 보류했다. 현재 운영 개선 대장의 출시 안전·실사용 측정·고객응대 과제를 먼저 본다.
- 기존 운영 보고서와 로컬 정책·화면 코드를 읽기 전용으로 재대조했다. 공유목록 접근 권한·안전한 배포, 다이소 저장/비회원 초안 병합, 이용량 계측, 접수·회신 경로, 내 데이터 다운로드, 실제 참여자 과업 관찰이 남아 있다. **오늘 운영 DB 정책이나 배포본을 다시 실측한 결과는 아니므로** 9월 26일의 `확인`·`로컬 준비` 상태를 운영 완료로 올리지 않았다.

### 2026-09-27: 회원·비회원 릴리스 미리보기와 다이소 목록 카드 개선

- 원격 `main`을 기준으로 분리한 `release/member-guest-shared-20260927`에 회원·비회원·공유목록 변경(`a0e79ec`), 다이소 실제 로고(`6e09247`), 다이소 목록 카드 정보 개선(`91b7ac0`)을 커밋했다. 상품 랭킹 변경과 원래 작업 트리의 미완성 수정은 포함하지 않았다.
- 별도 Vercel 미리보기에서 공유 링크를 연 비회원의 로그인/가입 안내와 일반 지도 탐색, 다이소 실제 로고 표시, 비회원 별점 선택 뒤 계정 안내를 확인했다. 98개 파일의 921개 테스트, 타입 검사, 린트, 프로덕션 빌드가 통과했다. 브라우저 자동 E2E는 실행 환경의 Chromium 권한 오류로 앱 검증 전에 중단되어 수동 화면 확인으로 보완했다.
- Vercel에는 필요한 Supabase 변수 이름이 Production을 포함한 모든 환경에 존재한다. 그러나 현재 연결된 Supabase 대시보드 계정에서 운영 프로젝트가 보이지 않고 DB 연결 인증서 검증도 실패하여 운영 마이그레이션 이력·RLS·백업을 검증하지 못했다. 운영 배포와 DB 적용은 보류한다.

### 2026-10-04: 전체 서비스 데이터 경계 설계

- `설계 승인/로컬 계획`: [서비스 데이터·운영 구조 설계](service-data-architecture-design-2026-10-04.md)에 장소 공통 카탈로그, 영업시간·시설·샵 서비스, 정보 출처/수정 이력, 자체 리뷰와 외부 평점, 이미지 파일/권리 메타데이터, 별도 블로그의 승인 스토리 반영 경로를 정리했다. 오너가 장소 카탈로그를 첫 구현 대상으로 승인했고, [B1 병행 카탈로그 구현 계획](service-catalog-implementation-plan-2026-10-04.md)을 작성했다. B1은 로컬 DB 적재·전수 동등성 검사까지이며 앱/운영 DB 전환은 B2로 분리한다.
- 공식 상품 순위는 장소 DB와 별도인 Google 시트 → 검증된 게시 스냅샷 경로를 유지한다. 2026-09-27 시험 행은 게시본이 아니며, 정기 갱신과 앱 반영은 이번 작업으로 시작하지 않았다.
- 운영 DB 마이그레이션, 앱 조회 전환, 이미지 이전, 블로그 연결, 배포는 실행하지 않았다. 현재 작업 트리는 사용자 변경이 많고 `.git` 쓰기 권한이 없으며 Docker 데몬도 실행 중이지 않아 B1 SQL·pgTAP 실행을 완료했다고 표시하지 않는다. 다음 순서는 격리된 쓰기 가능한 작업 트리와 로컬 DB에서 B1을 실행하고, 운영 권한·백업 확인을 B2 안전 게이트로 두는 것이다.
- `로컬 준비`: 인증된 `mg1018-whatap` SSH로 최신 원격 `main`에서 분리 브랜치를 만들고 B1 manifest의 ID·내용 해시와 생성/검사 명령을 구현했다. 1,122개 원본과 1,008개 게시 장소가 manifest에 포함되며 관련 29개 테스트가 통과했다. Docker Desktop을 이 실행 환경에서 시작할 수 없어 pgTAP·SQL 적용·DB 적재/패리티는 진행하지 않았다. 서비스 운영 DB와 앱 화면은 변경하지 않았다.
- 같은 분리 브랜치에서 타입 검사·린트·전체 971개 테스트는 통과했다. `audit:data:check`는 최신 `main`의 기존 장소 감사 보고서가 오래되어 실패하며, 이번 manifest 코드는 장소 원본을 바꾸지 않았다. 감사 보고서 재생성/검토는 별도 릴리스 게이트로 남긴다.
- 검증된 manifest 부분 작업과 이력 문서를 `feat/place-catalog-shadow-20261004` 브랜치에 푸시했다. 다른 개발자는 이 브랜치에서 확인할 수 있으나 `main`·운영 서비스에는 반영되지 않았다.

## 다음 결정과 기록 방식

1. **릴리스 책임자와 경로:** 원격 변경을 보존한 통합 범위, 배포 접근, DB 백업/드라이런 및 되돌리기 방법을 정한다. 공유목록은 새 앱을 먼저 배포하고 권한 마이그레이션을 뒤에 적용한다.
2. **고객지원 책임:** 실제 지원 이메일 또는 채널, 평일 담당자, 대체 담당자와 회신 가능한 문의 방식의 결정을 기록한다. 미정이면 화면에서 접수·답변을 보장하지 않는다.
3. **데이터 다운로드 범위:** 현재 항목의 실패를 전체 오류로 처리하는 우선 수정과, 피드백·신고·공유목록까지 포함하는 전체 내보내기 설계를 구분해 결정한다.
4. **이용량 측정 정책:** 첫 100명 관찰을 시작할 사람과 채널, 익명 방문/재방문 기준, 동의·보유 기간, 내부 테스트 제외 방식을 정한다.

새 작업을 진행할 때는 `YYYY-MM-DD: 확인/로컬 준비/운영 검증/보류` 형식으로 날짜별 이력에 **근거, 변경 파일 또는 배포 ID, 실제 테스트 결과, 남은 조건, 결정자**를 추가한다. 개인정보·계정 ID·문의/리뷰 원문·비밀키는 이 파일에 쓰지 않는다. 현재 상세 상태는 [운영 작업 현황](current-status-2026-09-26.md), 실무 절차는 [회원 운영 지침](../../docs/member-operations-runbook.md)을 기준으로 확인한다.
