## 구현된 연결

| 관리자/고객 작업 | 반영 내용 |
| --- | --- |
| 메뉴명·설명·가격·소요시간·공개 상태 변경 | 고객 매장 메뉴와 예약 서비스 목록에 반영 |
| 담당자 이름·소개·메뉴 연결·공개 상태 변경 | 고객 담당자 선택 및 예약 가능 대상에 반영 |
| 매장/담당자 운영시간·휴게시간·휴무·특정일 운영시간 변경 | 예약 가능한 시간 다시 계산 |
| 고객 예약 제출 | 같은 DB의 예약 원장에 저장, 관리자 예약 목록 표시 |
| 관리자 확정·취소 | 고객 예약 상세·내역에 반영 |
| 고객 취소 | 관리자 목록 변경, 점유 시간 재오픈 |
| 계정 데이터 다운로드 | 해당 고객 본인의 예약 포함; 매장 고객 전체 내역은 포함하지 않음 |
| 계정 삭제 | 예약 연락처·메모 익명화, 활성 예약 취소 및 시간 해제 |

메뉴/운영 설정은 기존 `merchant_*` 테이블을 사용합니다. 예약 저장은 `customer_bookings`, 상태 변경 기록은 `customer_booking_events`에 남습니다. 화면에 복제된 메뉴·고정 시간표·가짜 성공 상태는 사용하지 않습니다.

고객 화면은 포커스 복귀 및 표시 중 30초마다 조회합니다. 관리자 예약 목록도 동일하게 갱신합니다. 관리자 저장 후에는 즉시 다시 조회합니다. 숨겨진 탭의 주기 조회는 중지합니다.

## 예약 절차

1. 서비스 선택 및 로그인
2. 담당자 선택(매장 단위 예약이면 생략)
3. 서울 시간 기준 날짜·가능 시간 선택
4. 서비스·담당자·총액·결제 안내 및 연락처 확인
5. DB 저장 후 실제 예약 상세로 이동
6. 고객 내 예약과 관리자 예약 목록에서 동일한 예약 확인

로컬 테스트 정책은 **현장 결제 / 관리자 확인 후 확정**입니다. 실제 온라인 결제·예약금 수납·자동 메시지 발송은 연결하지 않았습니다. 서버는 즉시 확정 방식도 지원하지만, 실제 매장의 확인 방식과 결제 정책은 운영자가 확정한 설정을 적용해야 합니다. 기존 예약금·수수료 가정은 임의로 운영 정책에 반영하지 않았습니다.

## 동시 처리·권한

- 인증된 사용자만 생성·본인 예약 조회/취소 가능
- 관리자 멤버십이 있는 매장 예약만 관리 가능
- 공개 API는 공개 메뉴·담당자·빈 시간만 제공하며 고객 정보는 반환하지 않음
- 예약 시간/인원/담당자 중복은 DB 트랜잭션에서 재검증
- 예약과 관리자 설정 저장은 동일한 매장 잠금 사용
- 기존 예약과 충돌하는 운영시간·정원·예약 단위 변경은 거절
- 기존 예약은 당시 서비스명·담당자명·가격·소요시간 보존
- 가격·서비스 정보·담당자 변경 후 이전 견적으로 제출하면 재선택 요청
- 동일 요청 ID 재전송은 기존 예약 반환; 응답 유실 시 중복 저장 방지
- 계정 변경 시 예약 폼 개인정보와 이전 응답 상태 초기화

예약 접수 기간을 줄이는 작업은 신규 접수 범위만 바꿉니다. 이미 저장된 예약은 유지합니다. 메뉴/담당자 비공개 처리 역시 기존 예약을 삭제하지 않습니다.

## 최초 연결 검증

- 앱 자동 테스트: 155개 파일, **2,101개 통과**
- 전체 TypeScript 검사 및 ESLint 통과
- 실제 로컬 PostgreSQL 검증 **56개 통과**: 권한, 공개/비공개, 가격 변경, 담당자 변경, 휴무, 일정 충돌, 고객/매장 취소, 즉시 확정, 계정 삭제, RLS
- 실제 동시 접속 **4개 시나리오 / 16개 검증 통과**: 마지막 슬롯 경쟁, 같은 요청 재전송, 운영시간 수정 선점, 예약 선점. `pg_stat_activity`의 실제 대기/차단 세션 확인
- 실제 Next API + Supabase 왕복 **84개 검증 통과**: 관리자 담당자/특정일 운영시간/가격 수정 → 고객 반영 → 예약 접수 → 관리자 확정 → 고객 취소 → 관리자 조회 → 시간 재오픈 → 본인 예약 다운로드
- 실제 PostgREST 카탈로그·가능 시간·고객 예약·관리자 예약 응답이 런타임 검증기를 통과
- DB lint: 새 예약 함수 오류/경고 없음. 기존 일정 검증 함수 경고는 별도 정리 대상
- 테스트에서 수정한 메뉴 가격·담당자 이름·운영시간은 원복. 취소된 로컬 테스트 예약은 연동 확인 예시로 유지

최초 연결 시 브라우저가 없어 클릭·스크린샷 검증을 하지 못했습니다. 후속 작업에서는 Chrome 연결이 확인됐으나 관리 정책 확인 실패로 로컬 페이지 접근이 차단되어 화면 검증은 여전히 남아 있습니다. 실제 API/DB 동작 검증과 화면 렌더링 단위 검증을 수행했습니다. 프로덕션 빌드는 이 환경의 Google Fonts DNS 제한 때문에 이전에 완료되지 않았으며, 이번 작업의 배포 완료로 간주하지 않습니다.
